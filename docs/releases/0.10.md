## Customer Testing Notes

Recommended customer validation:

- Run local validation on `skz-data-lv` after pulling the latest branch when
  validating configured backends and provider access.
- Use LAN validation only when the REST service is intentionally exposed and
  the service process already has backend/provider configuration.
- Use synthetic records for live MCP/REST write validation.
- Verify structured errors for unauthorized roles or unallowlisted MCP writes.
- Verify scope, provenance, leakage guard, and trace fields in successful
  responses.

Do not test by exposing secrets, raw database credentials, raw Phoenix
credentials, provider keys, or benchmark answer material.
